第十八轮按验证选定的448语义分支已接入显式加载入口。在40段已有视频的全部2048查询、三个种子上，在线特征、原始分数和类别逐值复现旧缓存；六项几何输出与同输入原D4RT逐值一致。真实B=2和旧224兼容检查也通过。本轮没有训练、重校准或新的泛化确认。

固定协议见 [OVIS_DINO_448_INTERFACE_PROTOCOL.md](OVIS_DINO_448_INTERFACE_PROTOCOL.md)。采用resolution448三头、背景偏移−1.5、同一冻结DINOv2/D4RT骨干及既定128→448/32×32 patch采样处理。

## 新入口与兼容

```python
import torch
from semantic.dino_interface import load_resolution_selected_adapter
from semantic.ytvis import load_video

adapter = load_resolution_selected_adapter(seed=0, device="cuda")
rgb = load_video(clip)[None].cuda()  # float32，0至1，128×128
outputs = adapter({
    "video": rgb.to(torch.bfloat16),
    "semantic_video": rgb,
    "query": query,
})
xyz = outputs["xyz_3d"]
categories = outputs["semantic_labels"]
```

新入口检查第十八轮summary、verification与frozen_selection指纹及验证选择一致性，随后复用原严格骨干加载器，加载对应冻结头/偏移。选择依据是验证成绩，不是确认成绩。`feature_size`只支持224/448；旧`load_selected_adapter`及默认构造仍224，没有自动改变旧调用结果。

双RGB输入继续要求形状、设备和范围合法，且float32语义图像量化为几何dtype后逐值等于几何video。几何原batch直接交给原模型；语义仅读取源RGB/u/v/t_src，不读取GT掩码、类别提示或目标/相机时间。整个适配器不能统一转BF16，语义骨干权重与线性头保留float32。上游须保留原RGB，不能从量化图像恢复唯一原色。

单元检查通过：两种网格、默认224、B=2、Q=1/Q=3、源时间/坐标影响、目标/相机时间一致性、两组偏移/重载、参数冻结、非法图像/查询/分辨率、双RGB对应及输入不变。真实模型只覆盖CUDA；CPU两种网格使用替身检查，不能声称CPU真实模型已验证。

## 本机全接口开销

RTX5060 Laptop、8GB。每案一次顺序计时，原几何先于完整接口；权重加载、哈希和CPU读图不计入。存在首次启动与缓存/分配顺序影响，以下不是标准吞吐基准。

| 448批量/每视频查询数 | 原几何中位耗时/秒 | 完整接口中位耗时/秒 | 完整接口范围/秒 | 峰值已分配 | 峰值预留 |
|---|---:|---:|---:|---:|---:|
