# 第十九轮：冻结448语义分支的完整接口验证

在实现和模型验证前固定此协议。本轮不训练、不重新校准、不消耗新视频，不是新泛化确认。复用第十八轮按验证选定的resolution448、种子0/1/2三头和−1.5背景偏移；骨干、128→448预处理、32×32 normalized patch384、像素中心双线性采样及float16缓存精度保持。

接口支持显式feature_size224/448，默认224及旧load_selected_adapter行为保持；新增load_resolution_selected_adapter从第十八轮冻结验证选择加载，而不是按确认分数挑头。加载检查报告/选择/权重/源码指纹和选择一致性。几何video保持BF16，semantic_video保留对应float32，严格形状、设备、范围及量化对应。原batch交给原几何模型；语义仅源RGB/u/v/t_src，不读取真值、掩码或目标提示。

预先固定验证：

1. 必要单元检查覆盖两种网格、默认224兼容、B=2/单多查询、源坐标时间影响、目标/相机时间不变性、偏移、重载、非法分辨率/输入、参数冻结及输入不变。
2. 第十八轮已有40段确认视频全部2048查询，三个种子，B=1；在线448特征、原始logits、类别与该轮保存缓存/输出比较。全部差异和类别变化报告，重算原总体、前景及逐视频F1，不因结果调整实现。
3. 每案与原D4RT相同BF16输入、相同批量的六项几何输出逐值比较。修改t_tgt+1及t_cam+3模8，再次比较原几何；语义分数和类别须逐值相同。不假设B=1与B=2的几何彼此相同。
4. 固定前两段549/191，真实B=2、每段2048查询、三种子，重复上述检查；语义与对应B=1比较。另固定旧224视频153、完整2048查询、三种子，复现第十五轮224旧缓存及分数，不重新调用整个旧40段实验。
5. 每案单次顺序计时、记录完整接口CUDA峰值已分配/预留显存，排除模型加载/哈希/读图。记录失败与OOM，不静默改范围；单次顺序记录不是标准吞吐基准。

保存固定代码、所有帧、模型、旧报告/选择/缓存/预测指纹，运行后核验；保存全部在线语义输出供独立复算，提交仅自有代码、报告及文本快照。不修改第十八轮指纹覆盖的脚本与协议。已处理模型视频仍460，147段剩余视频源帧类别元数据已检查。
