# 第十六轮：D4RT几何与DINOv2语义的真实推理接口

冻结语义头已接入原D4RT查询接口。在预先固定的3段视频、三个种子上，全部六项几何输出与同输入的原D4RT逐值相同；改变目标/相机时间后，语义logits和类别逐值相同。192个原缓存查询的三种子特征/语义原始logits均逐值复现，576次类别比较无变化。

这是对已观察视频的接口正确性验证，没有训练、重校准或新的泛化确认。第十五轮的确认成绩仍是此前独立模型对照成绩，本轮不能把小样本接口检查当作新性能提升。协议见 [OVIS_DINO_INTERFACE_PROTOCOL.md](OVIS_DINO_INTERFACE_PROTOCOL.md)。

## 接口与固定模型

新增`DinoSemanticD4RT`，直接委托原D4RT前向，保留原返回字段；另以源RGB帧、u/v、t_src提取DINOv2局部特征，输出：

| 字段 | 形状 | 含义 |
|---|---|---|
| 六项原几何字段 | 与原模型相同 | xyz_3d、uv_2d、visibility、displacement、normal、confidence |
| semantic_raw_logits | B×Q×26 | 原始类别分数 |
| semantic_logits | B×Q×26 | 类别0加既定−1.75背景偏移后的分数 |
| semantic_labels | B×Q | 校准分数argmax的类别ID |

使用第十五轮按验证选中的coverage80_sam_background语义头，种子0/1/2均检查，D4RT/DINOv2/语义头全部冻结。接口不读取GT类别、掩码或文本提示，t_tgt/t_cam只进入原几何分支。预处理、patch采样、float16特征量化及float32线性头与缓存协议一致。

输入为0至1的RGB `[B,T,3,128,128]`和原查询`[B,Q]`。推荐RGB及u/v保留float32；几何计算在CUDA BF16 autocast下接收原始同一输入，语义头保持float32，不应把整个适配器强制转换为BF16。

## 验证范围

固定第十五轮确认清单前3段：153、52、395；每段从2048个旧缓存查询等间隔取64个，再加8个覆盖各源时刻、角点、中心和非整数坐标的查询，共216个唯一查询、三个模型种子。选点不依赖类别或分数。

- 九个案例的原/改变目标相机时间两套查询，各六个几何字段，共108组输出数组全部逐值相同，最大/平均绝对差为零。
- 九个案例的语义时间一致性逐值成立，包括新增边界查询；所有校准/原始分数与argmax类别自洽且有限。
- 192个旧缓存点、三种子的在线特征及原始logits逐值相同，576次类别预测无变化；权重重载后输出逐值相同。
- 输入视频及查询在前向后未改变。模型参数均禁止梯度，训练模式被明确拒绝。
- 单元检查覆盖B=2、Q=1/Q=3、源帧/坐标确实影响语义、角点、非法形状/范围/时间/NaN、背景偏移、权重哈希与类别数不匹配、独立实例重载。
- 真实模型只测试CUDA B=1、每段72查询；不能将替身B=2测试外推为真实模型批量已验证。

## 输入RGB精度的实际差异

第一段另固定72查询，诊断将RGB从float32先量化为BF16的影响。对同一个BF16输入，接口几何仍与原D4RT逐值相同；但与float32 RGB的语义比较并不等价：

| 种子 | 原始语义logits最大绝对差 | 平均绝对差 | 类别改变数/72 |
|---|---:|---:|---:|
| 0 | 0.1194 | 0.0225 | 1 |
| 1 | 0.1289 | 0.0230 | 1 |
| 2 | 0.1209 | 0.0225 | 0 |

合计2/216个种子×查询比较改变类别，这不是GT准确率下降的估计。BF16输入已经丢失的颜色精度无法通过`.float()`恢复，故RGB保持float32是复现DINOv2缓存的明确输入要求。几何保持结论始终以**相同输入精度**为参照，不意味着将旧BF16输入换成float32后几何数值也相同。

## 单次运行成本

本机RTX5060、8GB，原D4RT先运行，完整接口后运行。每案一次顺序计时，没有重复择优；首段包含启动/缓存影响，不作为标准吞吐或速度优势结论。

| 视频 | 原几何前向/秒 | 完整接口三种子范围/秒 |
|---|---:|---:|
| 153 | 0.7503 | 0.0704–0.1522 |
| 52 | 0.0565 | 0.0701–0.0708 |
| 395 | 0.0564 | 0.0704–0.0751 |

完整接口CUDA峰值已分配约2376.5–2377.3MiB，预留2564MiB。权重加载、文件哈希和CPU视频读取不在前向计时中。更长视频、更高分辨率、大量查询、真实B=2的资源情况尚未测量。

## 调用方式

在本机已有第十五轮产物、公开骨干权重与源码的情况下：

```python
from semantic.dino_interface import load_selected_adapter
from semantic.ytvis import load_video

adapter = load_selected_adapter(seed=0, device="cuda")
# clip为已有manifest条目；query包含五个CUDA查询张量。
video = load_video(clip)[None].cuda()  # 保留float32 RGB
outputs = adapter({"video": video, "query": query})
xyz = outputs["xyz_3d"]
categories = outputs["semantic_labels"]
```

加载入口校验所选语义头、两个骨干及DINOv2源码commit；不会下载新权重或使用类别真值。当前API为冻结推理，不是新训练入口。

## 核验与下一步

真实输出与原模型、旧缓存分别比较，保存所有数值差。运行后再次核验帧文件、缓存、三个头和两骨干指纹，结果与协议一致；源码commit未变。运行环境及九案例闭合核验保存在独立记录中。

下一轮应扩大冻结接口验证至完整已观察视频的全部查询，检验真实B=2及查询批量资源；依旧不训练、不重新校准、不冒充新确认。另预先固定显式双RGB精度输入接口：几何保留原BF16输入、语义保留对应float32原图，并严格检查二者是同一视频的量化对应。这可以同时复现旧几何输入与语义缓存，不能通过调整权重或确认阈值掩盖精度差异。

本轮没有证明几何真值精度或官方D4RT基准成绩，也没有消耗新的确认视频；视频使用数仍420，模型未评价的187段源帧类别元数据已被检查。后续新方法仍需另立协议。
