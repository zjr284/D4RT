# 第十七轮：双RGB精度、完整查询及真实批量接口验证

本协议在运行前固定。只复用第十五轮按验证选定的coverage80_sam_background三种子头、背景偏移−1.75、两个冻结骨干及既定预处理。不训练、不校准、不选择新视频，不是新的泛化确认。

接口新增可选`semantic_video`：几何`video`保留原BF16输入，语义视频保留对应float32原RGB，形状/设备必须相同，且语义视频量化为几何dtype后必须逐值等于几何视频。没有该字段时维持第十六轮接口行为。所有原批次字段原样交给几何模型；语义只读取RGB、u/v/t_src，不读真值。真值仅供实验脚本复算已有指标。

预先固定检查：

1. 扩展单元检查：合法双输入、错误图像/形状/精度/设备拒绝，原几何委托、原float32接口、输入不变等旧检查继续通过。
2. 第十五轮已有40段视频全部2048查询，固定清单顺序，B=1，种子0/1/2。每段与原D4RT的相同BF16视频/查询输出逐值比较六项几何字段。目标时间+1、相机时间+3模8后再次比较；语义logits及类别必须逐值不变。
3. 在线float32语义特征与原float16缓存逐值比较；三种子原始logits与原保存预测比较，报告全部差异及类别改变数。复算总体/前景宏F1与每视频指标，检验是否复现原成绩，不以成绩调整实现。
4. 真实B=2固定清单前两段153/52，完整2048查询及三种子；原/变化时间的几何保持与语义时间一致性同上，语义与单视频调用、旧缓存比较。几何只比较相同B=2原模型，不假设B=1与B=2几何逐值相同。
5. 每例仅一次顺序计时，记录显存峰值；不是标准吞吐基准，模型加载/哈希/读图排除在前向计时外。任何失败或OOM保存后报告，不能静默缩减视频/查询范围。

记录源代码、帧、缓存、旧预测、旧报告及三头指纹，运行后再核验；两个骨干/官方源码指纹沿用第十五轮加载校验。保存完整在线语义输出供独立复算，缓存/预测数组不提交。已处理视频仍420段，187段剩余视频未作模型评价，但源帧类别元数据已检查。
