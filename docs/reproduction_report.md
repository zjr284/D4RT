# D4RT 本地 tiny 复现实验记录（2026-09-13）

本报告记录的是**非官方、合成数据、低内存 tiny 实验**，目的在于检验代码与科研流程，不是论文公开基准的成绩。论文主模型、数据规模和预训练权重均未在本机复现。

## 环境与 WSL 中断

- WSL2 / Ubuntu，Python 3.12，PyTorch 2.14.0+cu130，RTX 5060 Laptop（8 GiB 显存）。
- WSL 可见 RAM 约 7.4 GiB，swap 2 GiB。此前高内存训练并行运行其他 Python 任务时，内核日志出现 `Out of memory: Killed process ... (python)`；一次记录显示被杀进程匿名 RSS 约 4.4 GiB、空闲 swap 为 0。随后 WSL 连接中断。因此不能把中断归因于模型数值发散。
- 新的 `--low-memory` 模式把输入改为 96×96、8 帧、渲染 128×128、512 查询，限制 CPU 线程为 4，检查点每 25 步保存一次。4 步冒烟训练通过，`/usr/bin/time -v` 测得进程最大 RSS 2,304,644 KiB（约 2.20 GiB）；断点读取测试通过。完整三次训练均正常退出。
- 检查点先写临时文件再原子替换，保存模型、优化器、学习率调度器和 CPU/CUDA/合成数据 RNG 状态。若 WSL 再中断，使用原命令参数加 `--resume <同目录的 tiny_last.pt>`；最多重做上次检查点后的 24 步。仅关掉终端且 WSL 未重启时，也可在新终端这样续训。
- 另外做了真实中断/续训演练：在第 65 步检查点之后中断一个 200 步试验，再从检查点续训到第 200 步，日志恰有 200 条且最终正常退出。高内存配置防护也已实测：7.4 GiB WSL 上不加 `--force-high-memory` 会在模型初始化前拒绝运行。

## 训练协议

固定配置：tiny、8 帧、96×96、合成渲染 128×128、每 clip 512 查询、300 步、AdamW（权重衰减 0.03）、峰值学习率 1e-4、75 步 warmup 后余弦衰减至 1e-6、梯度裁剪 10、CUDA bf16。训练种子分别为 0、1、2；每步生成一个新的解析合成场景。`--low-memory` 和 `tiny` 均不是论文配置。

| 训练种子 | 第 1 步损失 | 第 300 步损失 | 历史最小损失 |
|---:|---:|---:|---:|
| 0 | 15.830 | 0.493 | 0.355 |
| 1 | 3.071 | 0.440 | 0.318 |
| 2 | 4.508 | 0.584 | 0.303 |

三次训练均写满 300 条有限值日志。逐步配置、指标和权重分别在 `checkpoints/repro_safe_seed0/`、`seed1/`、`seed2/`。不同步的训练损失不可直接当成同一场景的泛化能力对比。

## 固定场景评测

所有模型均在合成评测种子 42 的同 3 个场景上测试，深度/点云网格为 24×24，稀疏跟踪每场景 16 点。下表的 ± 是**三个训练种子所得场景平均值的样本标准差**。`eval.py` 的 APD3D、AJ、OA、Pose AUC 和覆盖率是本地代理计算，非相应公开数据集官方评测器。

| 指标 | 3 种子均值 ± 标准差 |
|---|---:|
| 深度 AbsRel，序列单一尺度 S ↓ | 0.1235 ± 0.0023 |
| 深度 AbsRel，序列尺度+平移 SS ↓ | 0.1240 ± 0.0011 |
| 相邻帧旋转误差 ↓ | 2.472° ± 0.157° |
| 相邻帧平移误差 ↓ | 0.445 ± 0.159 |
| 相机轨迹 ATE（Sim(3) 对齐）↓ | 0.143 ± 0.024 |
| 3D 跟踪 APD3D ↑ | 0.032 ± 0.056 |
| 3D 跟踪可见帧 L1 ↓ | 4.171 ± 1.017 |
| 点云 L1（均值平移对齐）↓ | 1.202 ± 0.072 |
| 原图焦距相对误差 ↓ | 2.079 ± 0.556 |
| 20 轮限制下的稠密占位覆盖率 ↑ | 0.342 ± 0.005 |

评测脚本使用 20 轮，低内存演示脚本只用 10 轮；两者的覆盖率**不能相互比较**。

相同评测场景下，seed 0 未训练权重到训练后：深度 AbsRel(S) 从 3.220 降至 0.125，跟踪可见帧 L1 从 14.543 降至 3.050，点云 L1 从 1.502 降至 1.285；说明至少部分输出随训练改善。但相机旋转误差并未一致改善，焦距误差仍大于 100%，多数种子的绝对 3D 跟踪 APD3D 为 0。不能只挑改善指标声称全面复现成功。

## 动态感知相机配准：负面结果

在**同一 checkpoint、同一评测场景**上，仅将普通 Umeyama 改为可选的预测置信度/运动/可见性加权与 IRLS：

| 指标 | 普通 Umeyama | 动态感知版 |
|---|---:|---:|
| 旋转误差 ↓ | 2.472° | 2.494° |
| 平移误差 ↓ | 0.445 | 0.441 |
| ATE ↓ | 0.143 | 0.147 |

小幅平移改善伴随旋转和 ATE 变差，因此**没有证据表明当前改动优于基线**。点集层面的 `research/dynamic_pose_benchmark.py` 使用真值运动（oracle）才有明显收益；它只验证加权配准器，不验证模型能可靠地预测静态点。下一步研究应先测运动线索的校准质量，再按动态面积、遮挡比例和速度分层做更大测试，而不是继续盲目增加复杂度。
